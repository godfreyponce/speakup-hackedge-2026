# check_reply: name a word only where it names an error (issue #28, folds #27) Implementation Plan

> **For agentic workers:** Build with `/build-ticket 28`. This is a single-task plan: build in the working tree on branch `issue-28` and leave the change uncommitted for gate 2. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `check_reply` stops rejecting a true note because a correctly said list word ("very") appears as plain English, and starts rejecting a note that makes a claim about a word the child never tried with an error ("Giraffe had gliding").

**Architecture:** One change, inside the per-sentence loop of `check_reply` in `speakup/summary.py`. A sentence's **subject** is its first word, or the word after a leading "on". A session word with an error counts as named wherever it appears in the sentence. A correctly said word, or an example word, counts as named only when it is the subject. A sentence that makes an error or verdict claim must have a session word with an error as its subject.

**Tech Stack:** Python 3, standard library only (`re`, `unittest`).

**Spec:** GitHub issue #28 and the owner's Nov 10 comment on it ("option 2. Match a list word only where it names an error, not anywhere in the sentence. Fold #27 into this build as well"). Issue #27 for the unknown-word case. No design spec in `docs/superpowers/specs/`. Neither issue had a Done when section. The owner said yes (Nov 10, via `/run-ticket`) to this one, written by the planner:

1. `check_reply` accepts "Truck had gliding (heard w), which is very clearly flagged for age." for the `--demo` session at 96 months.
2. `check_reply` rejects "Giraffe had gliding (heard w), which is flagged for age." for the same session.
3. Every reply the tests accept today still passes, and every reply they reject today still fails.
4. `python3 -m unittest` passes.

The owner also said yes to the naming rule in Architecture above (the mix of "errored words anywhere" and "correct words only as subject") and to the #27 rule (a claim sentence needs an errored session word as its subject).

## Decisions taken in this plan (gate 1)

1. **Errored words count anywhere; correct words only as subject.** The owner said yes. It fixes "very" and still catches "Rabbit and red had gliding" when red had a distortion (a subject-only rule would let that through).
2. **A claim sentence needs an errored session word as its subject (#27).** A "claim" is a sentence that holds an error phrase (`ERROR_WORDS` values: "gliding", "distortion", "the r sounded off") or a verdict key ("flagged", "normal", "keep an eye"). The owner said yes. Known cost: a true note shaped "The r sounded off in rabbit, ..." or "Very clearly, truck had gliding ..." is now dropped. The end screen then shows the tally only, as for any rejected note. No measured reply has that shape.
3. **Subject = first `[a-z]+` run of the lowercased sentence, after an optional leading `on `.** This covers both shapes the measured replies use: "Rabbit had ..." and "On carrot, the r ...".
