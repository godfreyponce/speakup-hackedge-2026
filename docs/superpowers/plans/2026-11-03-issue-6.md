# Session log: what the therapist sees later (issue #6) Implementation Plan

> **For agentic workers:** Build with `/build-ticket 6`. This is a multi-task plan: build on the ticket branch `issue-6`, one commit per approved task. **Task 2 ends with a stop for the owner to pick a mockup**; the build resumes on the owner's reply. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every finished session is saved in SQLite on the board, and the therapist can open a list of all sessions and a page per child ID that shows that child's sessions in order.

**Architecture:** A new `speakup/store.py` owns the database: it saves a finished `Session` (one `sessions` row, one `results` row per word, in one transaction) and reads sessions back as `SavedSession` values. It opens a fresh connection per call, so the server thread and the test thread never share one. The server saves the session when the last Next finishes it, and serves two new pages, `GET /sessions` and `GET /child/<child_id>`, rendered in `speakup/pages.py` from the mockup the owner picks.

**Tech Stack:** Python 3, standard library only: `sqlite3`, `contextlib`, `http.server`, `html`, `unittest`.

**Spec:** GitHub issue #6 ("Session log: what the therapist sees later"). It builds on #5 (`speakup/session.py`, `speakup/server.py`, `speakup/pages.py`, the look in `mockups/issue-5/c3-bubble.html`), #3 (`Result`), and #4 (`should_flag`, age in months). All are merged on main.

## Global Constraints

- "Sessions and their per-word results (#3) are saved in SQLite on the board." Standard library `sqlite3`; no new dependency.
- "The database file is in `.gitignore`." Data rule: "never commit audio or any child data." Tests use temp folders and made-up IDs (`S-014`).
- Out of scope, from the ticket: "Logins, export, sync to anywhere. One board, one therapist, offline."
- Pages follow #5's rules: one HTML document each, inline CSS, no JavaScript, nothing loaded from off the board (no `://` in the page, so an inline `<svg>` leaves out `xmlns`). Every value in HTML goes through `html.escape`.
- Flags come from `should_flag(error_type, target_sound, age_months)`, never from a second copy of the rule.

## Decisions taken in this plan (gate 1)

1. **Save once, when the session is finished.** The last `POST /next` (the one that ends on the summary) saves the whole session in one transaction. A session that is left halfway (a new Start, a closed browser, a power cut) is not saved. Reason: an unfinished screen is not a screen, and the log never holds half sessions. Alternative: save at Start and at each Record (Record again replaces the row), so a power cut loses nothing; the list then needs a "4 of 10 words" column and a way to show unfinished sessions.
2. **Flags are worked out when a page is read, not stored.** The database stores the age in months and each #3 result as it came from the model. The list and the child page run `should_flag` on them. Reason: one rule for every session, the same rule as `pass_or_refer`, so the sessions of one child compare fairly. Cost: if Lexi changes a norm (the 96-month distortion line waits on her), old sessions show the new answer. Alternative: store a `flagged` column at save time, which freezes what the screen said that day.
3. **Order is the save order (`sessions.id`), not the clock.** The child page lists oldest first, so a change reads top to bottom. The list page shows newest first. Reason: the board has no clock battery yet (#1 tracks an RTC), so its dates can be wrong or jump; the save order is always right on one board. The date is still shown.
4. **Session date is when Start was pressed**, set in `Session.__init__` as `datetime.now().astimezone().isoformat(timespec="seconds")`, shown as `2026-11-05 10:15`.
5. **The database file is `data/speakup.db`.** `data/` is already in `.gitignore`; the plan also adds `*.db`, so a copy anywhere else in the repo stays out too. No `--db` flag (nothing asks for one); tests pass a temp path to `make_server`.
6. **Routes: `GET /sessions` and `GET /child/<child_id>`.** The child ID goes in the path, checked with `parse_child_id` (letters, digits, hyphens). An ID that fails that check, or that has no saved session, gives 404. The start page gets a "Past sessions" link to `/sessions`; each list row links its child ID to `/child/<id>`; both new pages link to `/` ("New session") and the child page links back to `/sessions`.
7. **The list shows exactly the ticket's four columns:** date, child ID, age (`7;4`), number of flags. Nothing more.
8. **Visual rule.** `AGENTS.md`'s `# Visual rule` says **3** variants (the global command says 4; the repo section wins). Its folder and keep-or-delete fields are still template placeholders, so this plan follows #5: the variants go in `mockups/issue-6/`, the winner's layout and CSS are wired into `speakup/pages.py`, and the losers are deleted before the Task 2 commit. The global command asks for all variants on **one page** with the data defined once, and the repo rule does not forbid it, so the three variants share one file. The look stays #5's speech-bubble strip (`mockups/issue-5/c3-bubble.html`: its font, colors, chips, and table); the three variants differ in the **shape of the child page**. **References, for the owner to confirm or replace at gate 1:** (a) #5's own summary table, the look this app already has; (b) the Goldman-Fristoe (GFTA-3) record form SLPs fill in, a grid of words with a mark per sound; (c) an SLP progress-monitoring sheet, the line graph of errors per session that therapists keep for IEP goals. No variant is built before the owner confirms the references.
9. **Board risk, not fixed here: `sqlite3` may be missing from the board's Python.** The board runs TI's Yocto image (`tisdk-default-image`), where Python's `sqlite3` module ships as a separate package (`python3-sqlite3`). If it is not installed, `python3 -m speakup` fails at import. The fix, if needed, is on the board, not in this code. The proposal: the owner adds `python3 -c "import sqlite3"` to #13's checklist.

## Review Focus

1. **Record again, then Next:** only the last result per word is saved, and a word appears once. Pinned by `test_finished_session_is_saved` (Task 3), which records rabbit twice.
2. **Refresh or Back on the summary** (a second `POST /next` after done): the session is saved once, not twice. Pinned by `test_finished_session_is_saved` (Task 3).
3. **The age rule at read time:** the same gliding error flags at 7;0 and does not flag at 6;11, on the list and the child page. Pinned by `test_flag_count_uses_age_rule` (Task 1) and `test_child_page_shows_sessions_in_order` (Task 3).
4. **A typed URL with a bad or unknown child ID** (`/child/S-999`, `/child/..`, `/child/S-014/x`): 404, no crash. Pinned by `test_child_page_unknown_or_bad_id_is_404` (Task 3).
5. **The first run on a fresh board** (no `data/` folder, no database): the list page shows an empty list and the first save creates the folder and file. Pinned by `test_empty_store_and_folder_created` (Task 1).

Not covered, by design: a failed write (full or read-only SD card) drops the connection like #5's other unhandled errors; a board clock that is wrong shows wrong dates (order stays right, Decision 3); two boards' logs are never merged (out of scope).

### Task 1: The store: save a session, read sessions back

**Files:**
- Create: `speakup/store.py`
- Modify: `speakup/session.py` (add `started_at` in `Session.__init__`), `.gitignore` (add `*.db`)
- Test: `tests/test_store.py`

**Interfaces:**
- Consumes: `Session`, `Attempt` from `speakup/session.py`; `Result` from `speakup/result.py`; `should_flag` from `speakup/age_norms.py`.
- Produces:
  - `Session.started_at: str`, ISO 8601 with offset, seconds precision, set at construction.
  - `@dataclass(frozen=True) class SavedSession: id: int; child_id: str; age_months: int; started_at: str; results: list[Result]`, with `is_flagged(self, r: Result) -> bool` (calls `should_flag(r.error_type, r.target_sound, self.age_months)`) and `flag_count(self) -> int`.
  - `save_session(db_path: Path, session: Session) -> int`: inserts the session and `[a.result for a in session.attempts]` in one transaction; returns the new `sessions.id`.
  - `load_sessions(db_path: Path, child_id: str | None = None) -> list[SavedSession]`: every session, or one child's, oldest first (`ORDER BY id`), each with its results in word order.
  - Both create `db_path.parent` and the tables (`CREATE TABLE IF NOT EXISTS`) on every call, and close the connection when done (`contextlib.closing`; `with conn:` commits but does not close).
  - Schema:

```sql
CREATE TABLE IF NOT EXISTS sessions (
  id INTEGER PRIMARY KEY,
  child_id TEXT NOT NULL,
  age_months INTEGER NOT NULL,
  started_at TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS results (
  session_id INTEGER NOT NULL REFERENCES sessions(id),
  position INTEGER NOT NULL,
  word TEXT NOT NULL,
  target_sound TEXT NOT NULL,
  expected_phone TEXT NOT NULL,
  heard_phone TEXT,
  error_type TEXT,
  confidence REAL,
  model TEXT NOT NULL,
  recorded_at TEXT NOT NULL,
  PRIMARY KEY (session_id, position)
);
```

  The `results` columns are `speakup.result.FIELDS` in order; select those columns by name and build `Result(**dict(zip(FIELDS, row)))`, so a field added to #3 later fails loudly instead of shifting columns.
