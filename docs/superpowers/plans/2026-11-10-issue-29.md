# End screen: tally at once, note when it arrives (issue #29) Implementation Plan

> **For agentic workers:** Build with `/build-ticket 29`. This is a single-task plan: build in the working tree on branch `issue-29` and leave the change uncommitted for gate 2. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the last word is done, the session is saved and `/summary` shows the tally and the pass, watch or refer line at once. Qwen's note is written in a background thread, the end screen says "being written" and reloads itself, and the note shows when it is ready.

**Architecture:** The note moves off the request. `SpeakUpServer` gets a `threading.Lock` that guards three fields (`session`, `note`, `note_pending`) wherever the request and the note thread can meet. `/next` marks the note pending, starts one daemon thread per finished session, and saves at once. The thread runs today's `note()` call and writes the result only if `server.session` is still the session it was written for. While the note is pending, `summary_page` adds a "being written" line and a `<meta http-equiv="refresh">` tag, so the page reloads with no JavaScript.

**Tech Stack:** Python 3, standard library only (`threading`, `http.server`, `unittest`).

**Spec:** GitHub issue #29 ("End screen: show the tally at once, add Qwen's note when it arrives"). It changes the note flow from #9 (`docs/superpowers/plans/2026-11-03-issue-9.md`). No design spec in `docs/superpowers/specs/`.

## Data flow

No data-flow change: the note still comes from `generate` and goes only to the end screen, the session save still writes `data/speakup.db`, and `summary note skipped: <reason>` still goes to stderr. Only the time and the thread of the `generate` call change.

## Decisions taken in this plan (gate 1)

1. **One lock, not a lock-free trick.** The module docstring says "nothing needs a lock". That stops being true when a second thread writes the note. Without a lock, the thread can check "is this still my session?" and then, before it writes, a new `/start` can clear the note. The thread then writes the old note onto the new session. A `threading.Lock` (`server.note_lock`) around the check-and-write, the reset in `/start`, and the read in `/summary` closes that gap. The docstring's second sentence changes to say so.
2. **The page reloads itself every 3 s while the note is pending.** The tag is `<meta http-equiv="refresh" content="3; url=/summary">`. 3 s is a guess: the board note takes about 40 s (Raf, #26), so the note shows at most about 3 s late and the page reloads about 13 times. The `url=/summary` part is required, not style. The failed-save page is the response body of `POST /next` or `POST /save`, and a bare refresh would reload `/next` as a GET, which is a 404.
3. **No HTML variants.** The visual rule covers new looks. This change adds one text line in the existing `.note` paragraph style (`<p class="note">Summary note: being written on the board.</p>`, the ticket's own example words). It adds no layout or style. If the owner wants variants, say so at gate 1. (AGENTS.md's `# Visual rule` still has its template placeholders for the folder and wiring.)
4. **"No `--llm-bin`" means no model.** The Done when says "With no `--llm-bin`, the end screen is the same as now". In the code, the model is off when `server.generate is None`. That is the case with no `--llm-model`, or when `llm.load` fails at start. `--llm-bin` has a default (`llama-completion`). The plan tests `generate = None`.
5. **Tests wait on the thread, not on the clock.** The server keeps the last note thread as `server.note_thread`, and the tests `join()` it. Polling `/summary` until the line goes away would also work, but it needs a sleep and a deadline. The join timeout in the tests is 5 s, a guess with no receipt. It only stops a broken test from hanging, and every fake answers at once.
6. **A side effect the owner should know about:** #9's deferred note "a hung llama.cpp blocks the one-request server for up to 120 s" goes away, because the request no longer waits on llama.cpp. During a note, the note and #21's bank fill can run llama.cpp at the same time. That was already possible before this change.

## Review Focus

- **A note error that is not `LlmError` or `ValueError`.** If the thread dies before it clears `note_pending`, the page says "being written" and reloads forever. The thread clears `note_pending` in a `finally`. Test: `test_unexpected_note_error_clears_pending_line`.
- **The failed-save page while the note is pending.** It is the body of a POST, so its reload must go to `/summary` (Decision 2). Test: `test_failed_save_keeps_note`, which this plan rewrites.
- **A second session that finishes while the first note is still being written.** The old thread must not write its note on the new screen, and must not clear the new screen's "being written" line. The session check in the thread covers both. Test: `test_old_note_dropped_on_new_session`.
- **Reload of `/summary` after the note is ready.** No second `generate` call and no refresh tag. Test: `test_summary_shows_model_note` (keeps its one-prompt assertion).
- **The pending line and refresh tag with no model.** Neither may show. Test: `test_end_screen_works_with_no_model`.

**Interfaces:**
- Produces, in `speakup/pages.py`:
  - `_page(title: str, body: str, css: str = CSS, head: str = "") -> str`. `head` goes into `<head>` right after the viewport `<meta>`.
  - `summary_page(session: Session, save_error: str | None = None, note: str | None = None, note_pending: bool = False) -> str`. When `note_pending` is true: the body has `<p class="note">Summary note: being written on the board.</p>` where the note paragraph goes today, and `head` is `<meta http-equiv="refresh" content="3; url=/summary">`. When false: the page is the same as today.
- Produces, on `SpeakUpServer` in `speakup/server.py`:
  - `note_lock: threading.Lock`
  - `note_pending: bool` (starts `False`)
  - `note_thread: threading.Thread | None` (starts `None`; tests join it)
  - `start_note(self, session: Session) -> None`: if `self.generate is None`, do nothing. Otherwise, under the lock, set `note = None` and `note_pending = True`, then start a daemon `threading.Thread(target=self.write_note, args=(session,))` and keep it in `note_thread`.
  - `write_note(self, session: Session) -> None`: the thread body, moved here from `Handler.write_note`. It sets `text = None`, then calls `text = note([a.result for a in session.attempts], session.age_months, self.generate)` and catches `(LlmError, ValueError)` with today's `print(f"summary note skipped: {e}", file=sys.stderr, flush=True)`. In a `finally`, under the lock, if `self.session is session`, set `self.note = text` and `self.note_pending = False`. Any other exception propagates after the `finally` and Python's thread hook prints it.
  - `note_state(self) -> tuple[str | None, bool]`: returns `(note, note_pending)` read under the lock.
- `Handler` changes:
  - `/next` when `session.done`: `self.server.start_note(session)` then `self.save(session)`. `Handler.write_note` is removed.
  - `start`: the three lines `session = ...; save_error = None; note = None` go under `with self.server.note_lock:`, and they also set `note_pending = False`. The screen's `Session(...)` call can stay outside the lock.
  - `/summary` GET and `save`'s 500 page: `note, pending = self.server.note_state()`, then `pages.summary_page(session, error, note, pending)`.
