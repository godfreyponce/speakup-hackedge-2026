# Practice coach, part 1: levels, startup bank, line check (issue #21) Implementation Plan

> **For agentic workers:** Build with `/build-ticket 21`. This is a multi-task plan: build on branch `issue-21`, one commit per approved task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A practice mode beside the 10-word screen. The child says one item, Arti (or `--demo`, or the fake) scores it, plain code moves the level (word, phrase, sentence) one step up on a right r and one step down on a miss, and the next line comes from a bank that Qwen fills at startup under a GBNF grammar. Code checks every line first. Every try lands in the log with the age rule and the pass/refer line.

**Architecture:** Three new modules. `speakup/bank.py` holds the kid word list (no r), the line checker, the grammar and prompt builder, the reply parser, and the `Bank` (one line per word and level). `speakup/practice_lines.csv` is the fixed fallback bank. `speakup/practice.py` holds the level rule and the `Practice` state. `llm.py` gains an optional grammar and reply length and a larger context. The server serves the fallback bank at once and swaps in Qwen's bank from a background thread when it is done, so start-up never waits on llama.cpp. `store.py` adds two nullable columns, `level` and `line`, to `results`.

**Tech Stack:** Python 3 standard library, `unittest`. Planning used Homebrew `llama-completion` (build 11960) and Qwen2.5-0.5B Q4_K_M at `/Users/geovponce/Developer/Hackedge-2026/models/qwen2.5-0.5b-instruct-q4_k_m.gguf`. The board's llama.cpp is b11146 (Raf, #26). The build does not need the model; the tests use fakes.

**Spec:** GitHub issue #21 and its one comment (Lexi's answer on levels, Nov 3). Board status: #26.

## Decisions taken in this plan (gate 1)

1. **Levels: word, phrase, sentence, as the ticket plans.** Lexi's clinical order is phoneme, word, multisyllable, sentence. Phoneme is out because Arti was trained on words and cannot score an r alone. Multisyllable is out because it needs new words Lexi has not approved; three of her ten words (rabbit, carrot, rocket) already have two syllables. Her answer says levels are "a great idea for screening purposes", so the plan reads it as OK for a leveled screen and practice tracker, not therapy. The UI says "practice" and "screening aid", never "therapy".
2. **Phrase and sentence tries are scored on the whole clip, as the word screen is.** `listen(target_word, clip)` gets the target word; Arti scores the loudest 1.5 s of the clip (`arti.WINDOW_SECONDS`). Risk: a 6-to-8-word sentence can run past 1.5 s, so the window may not hold the target word, and the default clip is 3 s (`--seconds`). Every bank line holds exactly one r (the target), which helps. If the owner step 2 shows Arti cannot tell right from wrong inside a phrase or sentence, the follow-up ticket changes only the practice record step (for example, the child says the target word on its own after the line); the level rule, bank and checker stay. Also from #26: Godfrey's Mac mic got "off" on every clip, even "rabbit" said right (0.99). Until the board result is in, the demo of practice should run with `--demo`.
3. **The grammar locks each line's shape by part of speech, not only by word list.** Measured below: a target slot plus a free run of no-r words gave lines like "a small white very in the sun." and "a very". With parts of speech, every reply was a grammatical line. Shapes:
   - phrase, noun target: `det adj TARGET` ("a big rabbit")
   - phrase, "very": `det "very" adj noun` ("a very big toy")
   - sentence, noun target: `det (adj)? who verb det (adj)? TARGET "."` ("the little bunny sees a big rabbit.")
   - sentence, "very": `det who verb det "very" adj noun "."` ("the cat likes a very soft bed.")
   Every Lexi word is a noun except those in `INTENSIFIERS = frozenset({"very"})`. If Lexi adds a verb or adjective, it needs an entry, and a test names the words it treats as nouns so the change shows.
4. **Real-word check: the repo list, not CMUdict.** A word is real when it is one of Lexi's words in `words.csv` or in the kid word list in `bank.py`. That list is the one below, all common words for a young child, none with the letter r. Owner: say at gate 1 if you want CMUdict instead (it is a download).
5. **One llama.cpp call per level, one line per Lexi word.** The grammar is a JSON object whose keys are Lexi's words in `words.csv` order, each value locked to that word. Two calls in all (phrase, sentence); the word level is the word itself and needs no Qwen. A failed call, a broken reply or a failed line leaves that word's fallback line in place.
6. **The bank fills in a background thread; the per-call deadline is `llm.TIMEOUT_S` (120 s, still the #17 guess).** The server starts at once with the fallback bank and swaps in the full bank in one assignment when both calls are done. So a slow board never stalls start-up; a practice that starts early uses fallback lines. No new timeout number.
7. **Context `-c 1024`, bank replies `-n 400`.** Measured: the bank prompt is 106 to 121 tokens, its reply 75 to 152 tokens; the note prompt is 203 tokens with `-n 96`. 121 + 400 = 521 and 203 + 96 = 299, both under 1024. The grammar ends the reply when the JSON object closes, so 400 is a cap, not a target; the longest line the sentence grammar allows is about 15 tokens, 10 lines plus keys stay under 300.
8. **Which item comes next:** Lexi's words in `words.csv` order, round and round (try n is `words[n % len(words)]`), at the current level. One line per word and level. "Record again" replaces the current try, as on the screen. The level moves on Next, from the current try's result.
9. **The log:** a practice is saved as one session, each try a row in `results`, with two new nullable columns: `level` (`word`, `phrase`, `sentence`) and `line` (the text the child saw). Screen rows keep both NULL. Old databases gain the columns on open (`ALTER TABLE` when `PRAGMA table_info` lacks them). The log pages do not change in this ticket: a practice shows there as a session of its tries. Showing the level there is part 2's job.
10. **No variants for the practice pages.** They reuse the screen's components (top bar, speech bubble, heard line, flag line, buttons, verdict bubble, table). Two CSS additions only: `.word.line { font-size: 44px; }` so a sentence fits, and the start form grid gets one more `auto` column for the Practice button. If the owner wants the 3 variants the visual rule asks for, Task 5 becomes: build them in `mockups/issue-21/`, stop for the pick, then wire in. Raf's kid UI (#26, not yet a PR) also changes `pages.py` and `server.py`; this plan builds on today's main, and whichever lands second resolves the conflict.
11. **Practice end screen has no Qwen note.** The pass/refer line, the tally and a table of tries; the #9 note stays on the screen's end screen only. `pass_or_refer` is reused unchanged, so it says "words" where it means tries ("Refer: 2 of 7 words flagged ...").
12. **Drops are logged to stderr,** one line each, in the form `bank: dropped phrase line for rabbit: 'a big wabbit' (not a word: wabbit)`. On the board, stderr goes to the systemd journal.
