# Practice word list: Lexi's r words (issue #10) Implementation Plan

> **For agentic workers:** Build with `/build-ticket 10`. This is a single-task plan: the work stays uncommitted in the working tree for gate 2. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `speakup/words.csv` holds Lexi's list (the stand-in list with very for cherry and truck for giraffe), and the `--demo` script and the summary test fixtures follow the new words.

**Architecture:** No new code. The data file changes, and so do the two places that name the old words: the demo script's word-to-result table and the recorded model replies in the summary tests. Done-when item 2 ("#5 reads its words from that file") is already true: `speakup/__main__.py` calls `load_words()` (landed with #5, commit d607766 and later). The build only confirms it.

**Tech Stack:** Python 3, standard library only (`csv`, `unittest`).

**Spec:** GitHub issue #10, "Practice word list: the r words a child says", body and the one comment:

> **Lexi's word list changes (Nov 3, by text to Godfrey):** swap **cherry for very** and **giraffe for truck**, because the "ch" and "j" sounds are also late developing. Everything else on the stand-in list is fine: rabbit, rain, ring, rocket, carrot, car, door, bear.

## Global Constraints

- "The list should be one data file so the swap touches nothing else." The file stays `speakup/words.csv` with the `word,position` header; `speakup/words.py` does not change.
- Positions are exactly `start`, `middle`, `end` (`speakup/words.py` `POSITIONS`).
- Standard library only; it runs on the board.

## Decisions taken in this plan (gate 1)

1. **truck is `start`.** Its r is in the "tr" cluster at the front of the word. Lexi's text gave no position for it. The alternative is a fourth position (`cluster`), which would change `POSITIONS`, the loader and its tests; this plan does not do that. If Lexi says clusters count apart, that is a new ticket.
2. **Row order groups words by position**, as the file does today: rabbit, rain, ring, rocket, truck, carrot, very, car, door, bear. very takes cherry's row. truck moves from giraffe's 7th place to 5th, so a presenter who rehearsed the old order hears the second gliding word earlier.
3. **The demo keeps three errors.** truck takes giraffe's result (`"gliding"`, the child says "twuck"); very takes cherry's (`None`). README's line "Enter an age of 8 years or older so every scripted error flags" stays true.
4. **The summary fixtures are re-measured, not just edited.** This planning session ran the real model on the new demo session (see "What the planning session measured"). `DEMO_AT_96` becomes the new real reply. With truck in the list, the model's reply at 62 months is now correct, so no real wrong reply exists for the "wrong verdict" test any more. `DEMO_AT_62` therefore stays the Nov 3 wrong reply with "Giraffe" changed to "Truck", and its comment says so. The test still rejects it because of the rabbit sentence ("flagged for age" at 5 yr 2 mo, where gliding is normal). The alternative, keeping "Giraffe" in the string, leaves a word that is not in the session in a fixture.
5. **Old mockups and the #5 entry in `docs/HISTORY.md` keep cherry and giraffe.** They record what was true then (`mockups/issue-5/c3-bubble.html`, `mockups/issue-6/c-chart.html`, HISTORY line 78). The accept-time docs commit adds a #10 section instead.
6. **No new test.** `test_shipped_list_loads_and_covers_every_position` and `test_script_covers_shipped_words` already fail on a bad list or a demo script that misses a word. A test that pins the ten words would pin data, not behavior.

## Review Focus

- A BOM or a stray space in the edited CSV: the loader already strips both (`utf-8-sig`, `.strip()`); the existing loader tests cover it.
- The demo server refuses to start when a list word has no demo line: covered by `test_script_covers_shipped_words`, which goes red if the CSV and `DEMO_OUTCOMES` disagree.
- The summary count: `DEMO` is built from `DEMO_OUTCOMES`, so a leftover `giraffe` key makes it 11 words and `DEMO_AT_96` ("10 words") fails. Swapping keys, not adding them, keeps it at 10.
- No other code names cherry or giraffe (checked: `grep -rn "giraffe\|cherry"` outside `.git` and old plans finds only the files in this plan, the two mockups and HISTORY).
