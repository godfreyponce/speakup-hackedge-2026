# Pick the board model and time it (issue #2) Implementation Plan

> **For agentic workers:** Build with `/build-ticket 2`. This is a multi-task plan: build on branch `issue-2`, one commit per approved task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Train Arti, a small right-or-wrong r classifier, on PERCEPT-R. Score it on the #14 test set, wire it into the app, and time it against wav2vec2 and the #7 summary model. Every number we can get without the board gets measured now, and the board run becomes a list of exact commands.

**Architecture:** `speakup/arti.py` is the app side of the model. It reads a 16 kHz WAV with the standard library, picks the loudest 1.5 s, and runs one ONNX file through ONNX Runtime, which TI's AM62x SDK ships. Then it returns a #3 result. Two laptop-only scripts (PyTorch, run through `uv`) train and export the model and export wav2vec2. `scripts/time_model.py` uses only `onnxruntime` and `numpy`, so the same command runs on the laptop now and on the board later. It times one ONNX model and, if asked, the llama.cpp summary while that model is loaded. The Nov 3 decision on #2 adds an error value `"off"` that reads "the r sounded off".

**Tech Stack:** Python 3 standard library for the app and tests. `onnxruntime` + `numpy` for running the model (laptop through `uv`; board from the TI SDK). Laptop only: PyTorch, torchaudio, onnx, onnxscript, transformers, huggingface_hub, all through `uv run --python 3.12 --with ...`. The laptop's own `python3` is 3.14 with none of these installed. llama.cpp from Homebrew (`/opt/homebrew/bin/llama-cli`).

**Spec:** GitHub issue #2 ("Pick the model that runs on the board, and time it"). Its Done when list, and the owner's **Decision, Nov 3** comment on it (points 1 to 4), quoted below. Test set and training rule: `docs/test-set.md` (#14).

## Decisions taken in this plan (gate 1)

1. **The board does not boot yet (#1: the SD card is dead and a new card is needed).** So this build measures everything on the laptop and writes the board run as exact commands in `docs/model-timing.md`. The board columns say "not run yet (#1)". The pick is made from laptop numbers. At gate 2 the builder files one new issue, "Run #2's timing on the board", with `Blocked by #1` as its first line and the commands in its body. Then #2 can close on accept. The other way is to keep #2 open until the board numbers exist. Done when boxes 1, 4 and 5 say "on the board", so this decision is the one most likely to be wrong.
2. **Arti is trained in this ticket.** No other ticket trains it, `docs/test-set.md` says #2 scores the model, and the Nov 3 decision says "our model learns from PERCEPT-R". The model is small (see 5), so training takes minutes on the laptop. Training for real is what makes "agrees with a trained listener" a measured number. If this ticket is too big for one build session, split here: Task 1 alone, then Tasks 2 to 5 as their own ticket.
3. **The error value is `"off"`**, and every screen and prompt shows it as "the r sounded off". The display text lives once, in `ERROR_WORDS` in `speakup/result.py`. `fake_model.py` and `demo_model.py` keep `gliding` and `distortion`, because the decision is about the real model. The `--demo` fallback still shows "w (gliding)".
4. **Arti's window is 1.5 s.** `prepare` picks the loudest 1.5 s of a clip and pads a shorter clip with silence at the end. Basis: in a 400-clip sample of the corpus, the span above 10% of the loudest 10 ms frame was 0.68 s at the median, 1.21 s at the 90th percentile and 1.41 s at the 95th. 18% of clips ran over 1.0 s, so a 1.0 s window would cut words. The app records 3 s (`--seconds 3`), so the window also skips the silence before and after the word. Timing still uses exactly 1.0 s of audio for every model, as the ticket asks. This works because Arti's time axis is dynamic.
5. **Arti's shape is a guess sized like a keyword-spotting model.** Log-mel frontend: 40 mel bins, 25 ms window (n_fft 400), 10 ms hop (160), Hann, 0 to 8000 Hz, `log(power + 1e-6)`. These are the common speech-commands settings. It is built as a fixed `Conv1d` DFT plus a mel matrix, so it exports to plain Conv/MatMul/Log ops. Body: 4 blocks of `Conv2d 3x3 → BatchNorm → ReLU → MaxPool 2`, channels 16, 32, 64, 64. Then global average pool and `Linear(64, 2)`, which comes to about 70k parameters. Training: Adam, lr 1e-3, batch 256, up to 20 epochs, keep the epoch with the best validation balanced accuracy, class-weighted cross-entropy. All of these are guesses with no tuning budget, and the doc says so.
6. **Training pool:** every clip from a child speaker (age 144 months or less) who is not in `test-speakers.txt`, any word, with a clear label (0.25 or less is wrong, 0.75 or more is correct, the same `listener_says` as #14). 10% of those speakers are held out for validation, seeded 2026 (10% is a guess). The script asserts that no test speaker is in either set.
7. **wav2vec2 is tried through ONNX Runtime, fp32 and dynamic int8.** That is the runtime the board has. PyTorch is not in TI's SDK list (TFLite 2.20.0, ONNX Runtime 1.23.2, Arm NN 26.01, from TI's AM62x SDK ML page). fp32 is about 1.2 GB, and the board has 2 GB of memory, so the int8 copy is the one with a chance to fit.
8. **The summary model timed is Qwen2.5-0.5B-Instruct, Q4_K_M GGUF** (`Qwen/Qwen2.5-0.5B-Instruct-GGUF`, file `qwen2.5-0.5b-instruct-q4_k_m.gguf`). It is the largest of #9's three picks, so if it fits next to Arti, the two smaller ones fit too. The reply is capped at 96 tokens (a guess for 2 or 3 sentences). The prompt is `build_prompt` from #7 on a made-up session.
9. **ONNX Runtime runs with 4 threads** (`intra_op_num_threads=4`) everywhere, which matches the board's 4 A53 cores. Laptop numbers are labeled as the laptop and are never presented as board numbers.
10. **`--arti` needs `--arecord`.** The laptop's fake recorder writes no file, so Arti would have nothing to read. argparse refuses the pair `--arti` without `--arecord`, and `--arti` with `--demo`.

## Review Focus

1. A 3 s board clip with the word in the middle: `prepare` must return the loud part, not the first 1.5 s. Pinned by `test_prepare_finds_the_loud_part`.
2. A silent clip (the mic was muted): `prepare` returns 24000 zeros, with no divide-by-zero. Pinned by `test_prepare_silence`.
3. A WAV that is not 16 kHz mono 16-bit (the onboard codec at 48 kHz, or a corpus file at 44.1 kHz): `read_wav` raises `ValueError` naming the format, which the app shows on the word page. Pinned by `test_read_wav_rejects_other_formats`.
4. `p_wrong` exactly at the threshold, 0.5: it counts as wrong, and both sides make a record that `check()` accepts. Pinned by `test_to_result_threshold`.
5. A test speaker leaking into training: `train_arti.py` asserts the sets are disjoint before it reads any audio. The real run shows it in its printed counts (no unit test, because the script needs torch).

**Interfaces:**
- Consumes: `ERROR_TYPES` with `"off"` (Task 1), and `result.check`.
- Produces, all in `speakup/arti.py`:
  - `RATE = 16000`, `WINDOW_SECONDS = 1.5`, `THRESHOLD = 0.5`, `MODEL_NAME = "arti-v0"`, `THREADS = 4`.
  - `read_wav(path: Path) -> list[int]`: reads with `wave`. It raises `ValueError(f"{path.name}: need 16 kHz mono 16-bit, got {rate} Hz, {channels} channel(s), {8*width}-bit")` for any other format.
  - `prepare(samples: Sequence[int]) -> list[float]`: always returns exactly `int(RATE * WINDOW_SECONDS)` = 24000 floats. It slides over 10 ms frame energies (sum of squares) and takes the loudest 24000-sample run. A shorter clip is padded with zeros at the end. The result is scaled so its largest absolute value is 1.0. All zeros stay all zeros.
  - `to_result(word: str, p_wrong: float) -> dict`: if `p_wrong >= THRESHOLD`: `error_type="off"`, `heard_phone=None`, `confidence=round(p_wrong, 2)`. Otherwise `error_type=None`, `heard_phone="ɹ"`, `confidence=round(1 - p_wrong, 2)`. `target_sound="r"`, `expected_phone="ɹ"`, `model=MODEL_NAME`, `recorded_at` as in `demo_model`. The return value is `asdict(Result(...))`.
  - `load(model_path: Path) -> Callable[[str, Path], dict]`: imports `onnxruntime` and `numpy` inside. It builds one `InferenceSession` (`intra_op_num_threads=THREADS`, CPU provider) and returns `listen(word, path)`, which does `to_result(word, float(p_wrong[0]))` on `prepare(read_wav(path))` fed as `audio` `[1, 24000]` float32.
  - `python3 -m speakup.arti MODEL WAV WORD` prints `json.dumps(check(result) as dict, ensure_ascii=False)`.
  - Train (Task 3) imports `prepare`, `RATE`, `WINDOW_SECONDS`. Time (Task 4) imports `THREADS`.
