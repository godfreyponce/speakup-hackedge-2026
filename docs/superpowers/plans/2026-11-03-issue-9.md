# Summary on the board (issue #9) Implementation Plan

> **For agentic workers:** Build with `/build-ticket 9`. This is a multi-task plan: build on branch `issue-9` with one commit per approved task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a session ends, llama.cpp runs Qwen2.5-0.5B-Instruct on #7's prompt, a code check tests the reply against the session's facts, and the end screen shows the reply as a "Model note". If the model is missing, fails, hangs or gets a fact wrong, the end screen stays as it is today: the verdict, the tally and the table.

**Architecture:** `speakup/summary.py` (#7) gets a chat-format prompt with one worked example, a `check_reply` that rejects a reply whose claims do not match the session, and `note()` in place of `summarize()`. A new `speakup/llm.py` turns a llama.cpp binary and a GGUF file into #7's `Generate` function, run as a subprocess, the same way `speakup/recorder.py` runs `arecord`. The server calls `note()` once, when the last word's Next is pressed, and keeps the result for the end screen. `python3 -m speakup` gets `--llm-model` and `--llm-bin`.

**Tech Stack:** Python 3, standard library only (`subprocess`, `tempfile`, `shutil`, `re`, `unittest`). llama.cpp `llama-completion`: Homebrew build 11960 on the Mac (`/opt/homebrew/bin/llama-completion`), and on the board a build from the vendored source (`/Users/geovponce/Developer/hackedge/vendor/llama.cpp`, commit b976279).

**Spec:** GitHub issue #9 ("Summary on the board: llama.cpp on the AM62x and the end screen"). It builds on #7 (`speakup/summary.py`, plan `docs/superpowers/plans/2026-11-02-issue-7.md`), #5 (`speakup/server.py`, `speakup/pages.py`) and #2 (`docs/model-timing.md`). #2 left two jobs for this ticket in `docs/model-timing.md`: "The prompt form and a check on what the model claims belong to #9."

## Decisions taken in this plan (gate 1)

1. **No HTML variants for the note.** The note is one paragraph on the existing end screen, in its current look: `<p class="note"><b>Model note:</b> ...</p>` under the Refer or Pass bubble and above the tally. #16 added its "Not saved" line and button the same way. The AGENTS.md `# Visual rule` section still holds template placeholders, so there is no folder for variants. If you want variants, say so: the plan then adds a mockups step before Task 3.
2. **A code check decides if the note shows.** `check_reply` rejects the reply, and the screen shows the tally only, if any of these is true:
   - it is empty;
   - it contains `pass`, `refer` or `diagnos` (any ending);
   - it contains a number that is not in the session's facts (the age's years and months, and the count of words);
   - one sentence names a session word that had no error, or an example word (`rope`, `bird`) that is not one of the session's error words;
   - one sentence says `normal` and names a flagged word, or says `flagged` and names a word that is normal for age;
   - one sentence uses an error phrase (`gliding`, `distortion`, `the r sounded off`) and names a word with a different error.
   This is strict on purpose: the screen sits under a Refer line that a therapist acts on. The cost: some sessions get no note (1 of the 6 measured).
3. **`note()` replaces `summarize()`.** The end screen already shows the code's line in the bubble, so it needs the model's text alone. `summarize()` has no other caller. `#7's model function calls it` holds through `note(results, age_months, generate)`, where `generate` is the llama.cpp function.
4. **The prompt is in ChatML, built in `summary.py`.** ChatML (`<|im_start|>` and `<|im_end|>`) is the chat format of all three models the ticket names (Qwen2.5 and SmolLM2). The one-example prompt needs several turns, which `llama-completion -cnv -st -sys` cannot send.
5. **The facts list only the words with an error, plus the count of words.** Correct words are not in the prompt, so the model has fewer chances to describe one wrongly. The check still rejects a reply that names one.
6. **The model runs in the request for the last Next, and once per session.** The end screen waits for it: about 1 s on the Mac; the board time is not measured yet (#17). A refresh or Save again does not run it again.
7. **The timeout is 120 s, a guess.** Nothing has measured the board yet. A hung llama.cpp must not freeze the demo. Tonight's run gives the number to tune it to.
8. **The model is off unless `--llm-model` is given.** This matches `--arti PATH`. A missing file or binary prints a warning at start, and the app runs with the tally only.
9. **The build ends at gate 2 with the Mac evidence. The board items are your steps tonight** (listed at the end). Proposal: land at accept, and close #9 after the board run ticks the first Done-when item.

## Review Focus

1. The model gets a fact wrong (verdict, error type, count, or a word with no error): the screen shows the tally only. Pinned by the `check_reply` tests in Task 1 and `test_wrong_model_claim_shows_tally_only` in Task 3.
2. llama.cpp hangs: after the timeout the screen shows the tally only, and the app keeps serving. Pinned by `test_hang_times_out` in Task 2.
3. The GGUF or the binary is missing at start: the app starts, says why on stderr, and shows the tally only. Pinned by the `load` tests in Task 2 and `test_end_screen_works_with_no_model` in Task 3; the start-up warning is checked by hand in Task 4, Step 3.
4. A refresh of `/summary`, or Save again, after a session with a note: the model is not run a second time, and the note stays. Pinned by `test_summary_shows_model_note` in Task 3.
5. The save fails in a session with a note: the 500 page shows "Not saved" and the note. Pinned by `test_failed_save_keeps_note` in Task 3.

Not covered, by design:
- A wrong phrase the check has no word for, such as "came out as w" for a distortion. The check knows only the three error phrases from `ERROR_WORDS`, plus `normal` and `flagged`.
- A board locale that is not UTF-8. The code reads and writes the prompt and reply as UTF-8 explicitly, but only tonight's run shows the board's behavior.
