# Arti: training-time spectrogram masking on fixed validation speakers (issue #19) Implementation Plan

> **For agentic workers:** Build with `/build-ticket 19`. This is a multi-task plan: build on branch `issue-19`, one commit per approved task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A validation-only runner that trains Arti 9 times (baseline, time mask, frequency mask, each with training seeds 2026, 2027, 2028), records each run, ranks the 3 methods by mean validation balanced accuracy, and a report of the 9 real runs. Nothing is deployed.

**Architecture:** `scripts/train_arti.py` keeps its CLI and its output. Its `train()` gains three keyword-only inputs (the init seed, an order generator, and an `augment` callable applied to each float32 CPU training batch) and returns the best epoch and that epoch's validation predictions too. The new `scripts/experiment_arti.py` reuses `index()`, `build_cache()` and `train()`, adds the two masks, and never imports or calls `export()` or `score()`. The report is `docs/arti-masking-experiment.md`.

**Tech Stack:** Python 3.12 through `uv run --managed-python`, with torch, torchaudio, onnx, onnxscript, onnxruntime and numpy (the existing laptop-only set; nothing new). The app and `python3 -m unittest` stay standard library: the new test module skips itself when torch is missing.

**Spec:** GitHub issue #19 (no comments). Background: `docs/model-timing.md` "How Arti was trained".

## Decisions taken in this plan (gate 1)

1. **Outputs go beside the zip, in `data/percept-r/arti-masking/`, weights included.** The ticket says "data/ and models/". This worktree is deleted at accept, so anything written to its own `data/` or `models/` is lost. The cache already lives beside the zip, so the results do too: one gitignored folder in the main checkout holds `results.json` and the 9 best-epoch state dicts (`<method>-seed<N>.pt`, about 250 KB each). The weights are kept so the follow-up can score or export the exact selected run without retraining it. `--out-dir` overrides the folder. If you want the weights under `models/arti-masking/` instead, say so; it is one default.
2. **Ranking is by mean balanced accuracy only, as the ticket says, with no margin.** Validation balanced accuracy swung 0.64 to 0.84 between epochs on Nov 3, so a small gap in the mean of 3 seeds may be noise. The plan adds no threshold (there is no basis for one). Instead the summary shows the standard deviation, the min and max, and the per-seed paired difference against baseline, and the report says in words when the gap is smaller than the seed spread. A candidate is "selected" only when its mean is strictly above baseline's; an exact tie keeps baseline.
3. **Seeds for the three generators come from `numpy.random.SeedSequence(seed).generate_state(3)`.** The init seed goes to `torch.manual_seed` (`Body()` has no generator argument), the order seed to a CPU `torch.Generator` passed to `torch.randperm`, and the mask seed to a second CPU `torch.Generator`. Using the training seed itself for all three would give the order and mask streams the same start. The production CLI path does not use this: `train()` with defaults still does `torch.manual_seed(2026)` and draws the order from the global generator, so the CLI trains the same model as before (Task 1 Step 6 proves it bit for bit on CPU).
4. **The real runs use the same device as `train_arti.py` (MPS when available).** Paired runs get identical initial weights and example order, but MPS float math is not guaranteed bit-identical between reruns. Reproducibility is proven on CPU in the tests; the report states the device and this limit. `--device cpu` exists for a deterministic rerun.

## Review Focus

1. **The cache does not match and gets rebuilt.** `build_cache()` rewrites `mels.npy` when the clip list differs. Expected on the real data: the log says `cache: reusing ... (42350 clips)`. Task 3 Step 2 stops the build if it does not. The end-to-end test checks that the cache bytes are unchanged.
2. **A masked value computed from float16.** The cache is float16. The mask must see the batch after `.float()`, so the fill mean is float32. Pinned by Task 1's `augment` contract and the test that the batch passed to `augment` is float32.
3. **The fill mean includes padding.** Short clips are padded with silence, so their log-mel has `log(1e-6)` frames and a lower mean. That is the ticket's rule ("original per-clip mean"); the report names it as a limitation. No code change.
4. **A rerun overwrites the earlier results.** `results.json` and the `.pt` files in the out folder are replaced. Expected and stated in the rerun instructions.
5. **A crash late in a long run loses finished runs.** `results.json` is rewritten after each run, so the runs done so far survive. The end-to-end test reads the final file only; the incremental write is one call inside the loop.

### Task 2: `scripts/experiment_arti.py`: masks, runs, ranking, CLI

**Files:**
- Create: `scripts/experiment_arti.py`
- Modify: `tests/test_arti_experiment.py` (add `MaskTest`, `SummaryTest`, `EndToEndTest`)

**Interfaces:**
- Consumes: `train()` from Task 1; `index`, `build_cache`, `SEED`, `VAL_SHARE`, `EPOCHS`, `BATCH`, `LR`, `CHANNELS`, `N_MELS`, `N_FFT`, `HOP` from `scripts.train_arti`. The module does `sys.path.insert(0, str(Path(__file__).resolve().parents[1]))` like `train_arti.py`, so `python -I` works. It does not import `export`, `score` or `session`.
- Produces:
  - `METHODS = ("baseline", "time", "frequency")`, `TRAIN_SEEDS = (2026, 2027, 2028)`, `TIME_MAX_FRAMES = 5`, `FREQ_MAX_BINS = 2`.
  - `stream_seeds(seed: int) -> tuple[int, int, int]`: `(init, order, mask)` from `np.random.SeedSequence(seed).generate_state(3)`, as Python ints.
  - `mask(batch: Tensor, axis: int, max_width: int, gen: torch.Generator) -> Tensor`: `batch` is `[B, n_mels, T]` float32; `axis` is 1 (frequency) or 2 (time). Per clip: width from `torch.randint(0, max_width + 1, (B,), generator=gen)`, then start from `(torch.rand(B, generator=gen) * (size - width + 1)).floor().long()` (widths drawn first, then starts). The band `[start, start + width)` on `axis`, across the whole other axis, is set to that clip's mean of the unmasked input (`batch.mean(dim=(1, 2))`). Returns a new tensor; the input is not changed. Width 0 changes nothing.
  - `augmenter(method: str, gen: torch.Generator) -> Callable | None`: `None` for baseline; `mask(b, 2, TIME_MAX_FRAMES, gen)` for time; `mask(b, 1, FREQ_MAX_BINS, gen)` for frequency.
  - `run_one(mels, labels, is_val, device, method, seed) -> tuple[dict, Body]`: times `train()` with `time.perf_counter()` and returns the record below and the body.
  - `summarize(runs: list[dict]) -> list[dict]`: one row per method, sorted by `(-mean_balanced_accuracy, METHODS.index(method))`, so baseline stays first on an exact tie. Row keys: `method`, `mean_balanced_accuracy`, `sd_balanced_accuracy` (`statistics.stdev`), `min_balanced_accuracy`, `max_balanced_accuracy`, `per_seed` (`{seed: bacc}`), `paired_difference` (`{seed: bacc - baseline bacc}`), `mean_missed_errors`, `mean_false_alarms`, `mean_best_epoch`.
  - `main(argv=None) -> int`: positional `zip_path`; `--out-dir` (default `<zip dir>/arti-masking`); `--device` (`auto`, `cpu`, `mps`; default `auto` = MPS when available, as in `train_arti.py`). Reads `test-speakers.txt` beside the zip, calls `index()`, prints the same clip and speaker count lines as `train_arti.py`, calls `build_cache()`, then for each seed in `TRAIN_SEEDS`, for each method in `METHODS`: `run_one`, `torch.save(body.state_dict(), out_dir / f"{method}-seed{seed}.pt")`, one printed line (method, seed, best epoch, balanced accuracy, missed, false alarms, seconds), and a rewrite of `out_dir / "results.json"`. At the end it prints the ranking.
- Run record keys: `method`, `seed`, `init_seed`, `order_seed`, `mask_seed`, `config` (`epochs`, `batch`, `lr`, `channels`, `n_mels`, `n_fft`, `hop`, `split_seed`, `val_share`, `mask` = `null` or `{"axis": "time"|"frequency", "max_width": 5|2, "fill": "clip mean log-mel"}`, `device`, `torch_version`), `best_epoch`, `balanced_accuracy`, `missed_errors` (listener wrong, predicted correct), `false_alarms` (listener correct, predicted wrong), `val_counts` and `train_counts` (`{"correct": n, "wrong": n}`), `train_seconds`.
- `results.json` keys: `speakers` (`{"train": n, "val": n, "test": n}` counts only), `clips` (`{"train": n, "val": n}`), `runs` (list of records), `ranking` (`summarize(runs)`, present only when all 9 runs are done). No speaker IDs, file names, or paths into the corpus.
